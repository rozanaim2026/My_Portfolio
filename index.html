What I built

  • Implemented JWT authentication, role-based authorization, Razorpay payment integration, Amazon SQS-based asynchronous payment processing, Amazon SES email notifications, and transaction-based order management.
  • Automated deployment using Jenkins, Docker, Amazon ECR, and Amazon ECS Fargate with Application Load Balancer routing, Amazon RDS MySQL, CloudFront, Route 53, and ACM for a production-ready cloud deployment.

APPLICATION PROJECT — ANDROID

Focus Bubble — a focus timer that survives being killed by the OS

Designed and developed an Android productivity application using Kotlin and Clean Architecture to help users stay focused through customizable study sessions. Implemented offline-first data persistence with Room Database and DataStore, secure Firebase Authentication, and lifecycle-aware timer management to ensure uninterrupted focus sessions even during app restarts or network interruptions.

Frontend repo ↗ Backend repo ↗

What I was solving for

  • Existing timer applications often lose progress when the app is backgrounded, the device restarts, or the operating system terminates the application.
  • Needed an offline-first solution that could reliably preserve focus sessions, user preferences, and authentication without depending on continuous internet connectivity.
  • Wanted a clean and maintainable Android architecture that separates business logic from the user interface for easier testing and future feature development.

What I built

  • Developed the application using Kotlin and Clean Architecture with separate presentation, domain, and data layers.
  • Built a timer state machine backed by Room and DataStore for offline-first persistence, synced against Firebase Auth.
  • Added customizable study timers, session tracking, and persistent local storage while maintaining a modular and testable codebase.

LEARNING PROJECT — SECURITY-FIRST DELIVERY

Tetris on the Cloud — putting security gates before the deploy, not after

Designed and implemented a complete DevSecOps CI/CD pipeline for deploying a containerized Tetris application on Amazon EKS. Automated infrastructure provisioning using Terraform, container image management with Docker, security scanning using SonarQube, Trivy, and OWASP Dependency Check, and GitOps-based Kubernetes deployments using ArgoCD.

View repository ↗

What I was solving for

  • Speed and safety usually get treated as opposites: fast pipelines skip scanning, safe pipelines get manual gates that people route around.
  • Manually clicking through cloud console setup drifts from whatever's actually in the repo within a week.

What I built

  • Declared the EKS cluster and VPC in Terraform, so "what infrastructure exists" is answerable by reading code, not the console.
  • Chained SonarQube (static analysis), OWASP Dependency-Check, and Trivy (image scanning) into the Jenkins pipeline as gates before deploy.
  • Handed off delivery to ArgoCD so the live cluster state is continuously reconciled against the Git manifests.

LEARNING PROJECT — MULTI-SERVICE RBAC

Cloud Conductor — least-privilege access across ten services, not one

A 10-microservice EKS platform with per-service RBAC and webhook-triggered CI/CD.

View repository ↗

What I was solving for

  • The more services share a cluster, the easier it is to default everything to broad permissions just to stop debugging access errors — which is exactly how one compromised service becomes a cluster-wide incident.

What I built

  • Scoped Kubernetes RBAC per service — dedicated ServiceAccounts, Roles, and RoleBindings, tied to AWS IAM through OIDC rather than shared cluster-admin credentials.
  • Triggered a multibranch Jenkins pipeline off GitHub webhooks so each service builds and deploys independently.
  • Scripted cluster and node-group setup with eksctl and Bash to keep provisioning repeatable.
